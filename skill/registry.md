# 智能体注册表（registry）

首脑派发前先读本表。每个专家一张「能力卡」；没有登记的专家不参与派发。

## 已敲定的方向
- 专家形态：**DSH 后台子智能体**（`subagent` 派发，可并行）
- 专家划分：**按角色**（通用型项目：编码 / 测试 / 评审 / 调研）
- 首脑宿主：本技能（DSH 会话内）+ 工作区 LangGraph 程序 `agent_hive/`（独立运行，同一套契约）

## 能力卡模板

```markdown
### 专家：<名字>
- 优势领域：<一句话，明确"接什么活最划算">
- 适用边界：<不接什么活，一句话>
- 证据：<能力可查证的出处：官网/文档/评测链接，或"本机实测通过"；没有证据 = 不派>
- 调用方式：<DSH subagent / CLI / API，附具体命令或入口>
- 输入：<接收什么格式，默认 contracts.md 的「任务工作包」+ 看板指针>
- 输出：<回传什么格式，默认 contracts.md 的「成果回传」（类型化工件）>
- 工具：<可用的工具清单，如 web 搜索、代码执行、数据库>
- 模型：<默认 deepseek-chat；成本敏感任务可降级>
- 成本：<每次调用的大致时间/费用，如"~1 元/次，10~60s">
- 工作区：<专家读写哪个目录，避免与别人冲突>
- 守卫：<输出必须通过的结构校验，如"交付物文件必须真实存在">
- 状态：<可用 / 维护中 / 待确认>
```

## 权限分层与情报来源

首脑获取智能体信息按用户开放程度分三档（详见 SKILL.md 步骤 0）：

| 档位 | 用户开放程度 | 首脑获取情报的方式 | 派发能力 |
|---|---|---|---|
| T0 全开放 | 允许自主访问环境 | 先要「定位提示」（指位置/先运行 agent）→ 窄探测建卡（预算 ≤10 次工具调用，超了先问用户）→ 联网调研佐证 | 可直接派发 |
| T1 部分开放 | 只开放某工作区 | 先定架构+分包，再请用户按「专家信息收集表」一次性回填 | 回填后分工派发 |
| T2 零披露 | 不开放 | 只产出架构+工程提示词包 | 不派发（顾问模式） |

情报来源按可靠度排序：①注册表能力卡（含证据链接）②用户回填（收集表）③首脑窄探测（仅 T0，先要定位提示，有预算）④联网调研佐证。

## 现有专家（按角色）

### 专家：编码 agent
- 优势领域：按工作包编写与修改代码、实现模块、补单元测试初稿
- 适用边界：不做架构决策、不改其他专家的工作区、不顺手重构无关代码
- 调用方式：DSH `subagent`（后台并行），prompt = 角色提示词 + 工作包 + 看板指针
- 输入：任务工作包（含接口契约、expected_output、depends_on、相关工件路径）
- 输出：成果回传（类型化工件：完成情况/交付物清单/自测/遗留/建议）
- 工具：读写文件、执行代码/命令
- 模型：deepseek-chat
- 工作区：`workspace/<包名>/`（与主仓库隔离，集成由首脑执行）
- 守卫：交付物文件必须真实存在于工作区，且能运行或有明确运行说明
- 状态：可用

### 专家：测试 agent
- 优势领域：把验收标准翻译成测试用例、执行测试、复现与定位缺陷
- 适用边界：不直接改业务代码，只产出测试与缺陷报告
- 调用方式：DSH `subagent`（后台并行）
- 输入：任务工作包 + 待测代码路径（从看板取依赖工件）+ 验收标准
- 输出：成果回传（通过项/失败项/缺陷最小复现步骤）
- 工具：读写文件、运行测试（pytest 等）
- 模型：deepseek-chat
- 工作区：`workspace/<包名>-test/`
- 守卫：每条验收标准都有对应测试或核查步骤
- 状态：可用

### 专家：评审 agent
- 优势领域：对照契约与编码标准审查交付物，逐条给出位置与改法
- 适用边界：不动手改代码，只出评审意见
- 调用方式：DSH `subagent`（后台并行）
- 输入：任务工作包 + 交付物路径 + 审查维度（契约符合性/标准/隐患）
- 输出：成果回传（问题清单：位置 + 差距 + 建议改法 + 严重度）
- 工具：只读文件
- 模型：deepseek-chat
- 工作区：只读
- 守卫：每条意见含位置+差距+改法+严重度四要素
- 状态：可用

### 专家：调研 agent
- 优势领域：联网调研、文档/API 事实核查、技术选型对比
- 适用边界：不写生产代码；结论必须带来源
- 调用方式：DSH `subagent`（后台并行），或 `/research` 技能
- 输入：调研问题清单 + 交付格式
- 输出：成果回传（结论 + 来源链接，区分事实/推断/建议）
- 工具：web 搜索（tavily）
- 模型：deepseek-chat
- 工作区：只读，产出写到 `workspace/<包名>-research/`
- 守卫：每条结论带来源链接
- 状态：可用

### 专家：外部程序 agent（占位，待完善）
- 优势领域：【待完善】例如"本机某个自建 LangChain agent 程序擅长的领域"
- 适用边界：【待完善】
- 调用方式：【待完善】例如 `uv run python agents/xxx.py "<输入>"`（确定后写死）
- 输入：命令行参数 / stdin JSON
- 输出：stdout JSON / 文件
- 工具：【待完善】
- 模型：-（程序自带）
- 工作区：【待完善】
- 守卫：【待完善】
- 状态：待确认

## 匹配规则（首脑用）
1. 优势领域精确命中 → 首选。
2. 相邻领域（如"编码"接"重构小任务"）→ 次选，派发时注明差距。
3. 无合适专家 → 停下问用户：是登记新专家、缩小范围，还是首脑自理。
4. 同一专家同批最多接 1 个包（除非它自己声明可并行）。
